# Project memory

- Plex HLS with `copyts=1` and `offset>0`: the playlist covers the whole file from 0, and segments before the offset are 188-byte PAT-only stubs. hls.js must start at `startPosition = offset`, and media time is absolute. Starting at 0 gives `fragParsingError` "Found no media in msn 0". (2026-10-23)
- Testing via CDP: do not mute the test video. Chromium pauses muted media when the window is not visible, which looks like a playback stall.
- Plex Discover watchlist: `X-Plex-Container-Size` above 100 gives status 400, so page by 100. The list has no `watchlistedAt`; get it from `/library/metadata/{ratingKey}/userState`. Match items to the server with `/library/all?guid=plex://…`. (2026-10-23)
- Moving a `<video>` element to a new parent pauses it. Multi-view redraws must call `play()` again on tiles that were playing.
- Multi-view tiles use volume 0, not `muted`, for the same Chromium reason as above.
- Plex ends an idle HLS transcode session after about 3 minutes (measured: 404 after 210 s idle, 200 with a ping every 30 s). A paused player must keep sending the timeline and `/video/:/transcode/universal/ping?session=…`. (2026-10-24)
- Embedded text subtitles on this server: with `protocol=hls&subtitles=auto` the decision says `location=segments-subs`, the HLS master has no subtitle playlist, and `/video/:/transcode/universal/subtitles` never answers (404 after 20 s). `/library/streams/{id}` gives 501 for embedded streams. Profile-extra rules did not change this. Only `location=sidecar` gives a file; otherwise burn at once. (2026-10-24)
- Web Audio boost needs `video.crossOrigin = 'anonymous'`, or direct-play media is tainted and the graph outputs silence. Tested: HLS and direct play both give sound through the gain node.
- Test streams change real watch state: the "stopped" timeline from `exit()` can arrive after a `scrobble`, and every scrobble adds to `viewCount`. Reset with a `stopped` timeline at time 0, then scrobble once.
- The friend's Plex server answers a browser GET with `Access-Control-Allow-Origin: https://app.plex.tv` for any other origin (also `null`), so a packaged TV web app cannot call it with fetch. plex.tv itself sends `*`. The webOS build sends blocked origins through its own JS service (`webos/service`) and plays HLS with the TV's native `<video>` player, which ignores CORS. Electron's `file://` pages skip CORS, so test the webOS build over `http://127.0.0.1` with the Origin header set to `null`. (2026-10-24)
- User rule (2026-10-25): every update and feature goes to all supported platforms (Windows desktop, Android TV, LG webOS). After each task: bump the patch version in the root `package.json` (Android and webOS read it), run `npm run build:all`, commit and push to main, then publish the six files from `dist/` (setup exe, its .blockmap, latest.yml, portable exe, APK, ipk) as a GitHub release; installed Windows apps update from latest.yml, so never leave it out `v<version>` so users can download them. The exe is over 100 MB, so builds go to Releases, never into git.
